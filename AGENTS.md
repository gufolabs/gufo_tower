# Gufo Tower — Agent Instructions

Web-based control plane for managing NOC cluster topology, node assignments, and service configuration. Backend: Python (Peewee ORM, Tornado). Frontend: WebIX bundled with esbuild. Distributed as Docker images or pip-installable wheels.

## Compatibility

* **Python**: 3.10+. All code must remain compatible with Python 3.10.
* **WebIX**: 5.4. Do not use APIs introduced in newer versions.

## Development

The canonical development environment is the VS Code dev container (`.devcontainer/devcontainer.json`). It provides Python, Node, uv, Playwright, Ruff, and other development tools.

`./scripts/run-dev` executes commands inside the running dev container via `docker exec`. It is not a virtualenv wrapper. It fails with exit code 7 if the container is not running.

Examples:

```bash
./scripts/run-dev pytest -v
./scripts/run-dev ruff check -q src/ tests/
./scripts/run-dev ruff format --check src/ tests/
./scripts/run-dev npm run build
```

## Build & Test

| Task                  | Command                                                                  |
| --------------------- | ------------------------------------------------------------------------ |
| Lint JS               | `./scripts/run-dev npm run lint`                                         |
| Build UI              | `./scripts/run-dev npm run build`                                        |
| Format check          | `./scripts/run-dev ruff format --check src/ tests/`                      |
| Lint Python           | `./scripts/run-dev ruff check -q src/ tests/`                            |
| Type check (optional) | `./scripts/run-dev mypy --strict src/`                                   |
| Tests                 | `./scripts/run-dev pytest -v --cov --cov-branch --cov-report=xml tests/` |
| Build package         | `./scripts/run-dev python -m build --sdist --wheel`                      |

Mypy is currently optional but is intended to become a required check in the future.

## Project Structure

```text
src/gufo/tower/       — Python backend
src/ui/               — WebIX frontend
src/ui/generated/     — generated UI sources; DO NOT EDIT
tests/                — pytest tests
docs/                 — MkDocs documentation
contrib/              — deployment configuration
```

## Architecture

* The production UI is built into `build/ui/` and included in the Python wheel. Do not make runtime depend on the UI source tree or an external `dist/` directory.
* When a WebIX combo uses data from the database, load its `options` explicitly in the appropriate `on_route_*` handler. Do not rely on implicit navigation loading.
* Environment-specific cached state must remain isolated by environment ID.
* Inventory collection is an explicit operation. Inventory fields may be absent.

## Conventions

* Import the package as `gufo.tower`, e.g. `from gufo.tower.models.db import db`.
* Python: 79-character lines, Google-style docstrings, Ruff formatting/linting.
* Imports: `stdlib → third-party → first-party`, according to `pyproject.toml`.
* Commit messages use an imperative description with PR number/link, e.g. `Home dashboard (#94)`. No component prefix.
* Create pull requests with GitHub CLI (`gh`).

## UI and Tests

* `src/ui/generated/` is generated by `scripts/build-generated.py`; never edit generated files manually.
* UI tests and the test suite actively use snapshots/screenshots. Preserve existing snapshots unless the visual change is intentional.
* The screenshotter is run manually by a developer inside the dev container:

  ```bash
  python -m docs.shotter
  ```

  Run it before a release or when there is reason to suspect that the rendered UI has changed. Do not run the screenshotter as part of normal development or test changes.

## Pitfalls

* Do not introduce implicit data loading that fetches an entire database collection when explicit options can be supplied.
* Do not assume optional inventory values are populated.
* Regenerate generated UI files only through `scripts/build-generated.py`.
* UI build output is `build/ui/`, not `dist/`.
* `build/ui/` must be present in the wheel produced by the package build.
